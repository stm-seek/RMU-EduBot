# RMU Academic Knowledge Base

ฐานข้อมูลหลักสูตร/รายวิชา/ตารางสอน ของ มรภ.มหาสารคาม สำหรับใช้เป็น
knowledge base ของ LINE chatbot ให้คำปรึกษาด้านการลงทะเบียน

**ใช้เฉพาะข้อมูลสาธารณะจาก `regis.rmu.ac.th` ไม่มีการ login และไม่เก็บข้อมูลส่วนบุคคล**

---

## ทำไมไม่ต้อง login

จากการทดสอบกับเซิร์ฟเวอร์จริง พบว่า **90% ของข้อมูลที่ระบบแนะนำการลงทะเบียนต้องใช้
เป็นข้อมูลสาธารณะทั้งหมด**

| ข้อมูล | ต้อง login? | แหล่ง |
|---|---|---|
| โครงสร้างหลักสูตร + เงื่อนไขจบ (120 นก.) | ไม่ | `program_info_1.asp` |
| รายวิชา + คำอธิบายรายวิชา | ไม่ | `class_info_5.asp` |
| วิชาเปิดสอนเทอมไหน + ตาราง + ที่นั่งเหลือ | ไม่ | `class_info_1.asp` |
| **วิชาที่นักศึกษาผ่านแล้ว** | **ใช่** | ต้องขอจากนักศึกษาเอง |

การ login ให้ข้อมูลเพิ่มแค่รายการเดียว → คุ้มกว่าถ้าให้นักศึกษาแจ้งเองผ่าน LIFF
(ติ๊กวิชาที่ผ่าน / อัปโหลดผลการเรียน) ซึ่งเลี่ยงประเด็น PDPA และเงื่อนไขการใช้ระบบทะเบียนได้

## วิธีใช้

```powershell
# เวอร์ชัน pin ไว้ใน requirements-dev.txt ที่ราก repo แล้ว
pip install -r ../requirements-dev.txt
```

```powershell
# 1) สร้าง database (idempotent เรียกซ้ำได้)
python -m kb.schema

# 2) ดูว่าคณะนั้นมีหลักสูตรอะไร (70 = เทคโนโลยีสารสนเทศ)
python -m kb.scrape_programs --faculty 70 --list-only

# 3) ดึงโครงสร้างหลักสูตร (59721 = MDI 643170151)
python -m kb.scrape_programs --faculty 70 --program-id 59721

# 4) ดึงคำอธิบายรายวิชา (วัตถุดิบของ RAG)
python -m kb.scrape_courses --program-id 59721

# 5) ดึงตารางสอนย้อนหลัง แล้วสรุปว่าวิชาไหนเปิดเทอมไหน
python -m kb.scrape_offerings --program-id 59721 --terms "2567/1,2567/2,2568/1,2568/2"

# 6) เก็บลิงก์เอกสาร/แบบฟอร์ม + ตรวจว่าลิงก์ยังเข้าได้จริง
python -m kb.scrape_documents            # seed + verify
python -m kb.scrape_documents --crawl    # หาลิงก์ใหม่จากหน้าที่กำหนด
python -m kb.scrape_documents --report-only

# 7) ข้อมูลอาจารย์ (+ เทียบกับคนที่สอนจริงในตารางสอน)
python -m kb.scrape_instructors --cross-check

# 8) ตรวจความถูกต้อง
python -m kb.verify 59721
```

ทุกคำสั่งรับ `--delay` (หน่วงระหว่าง request, default 1.0 วิ) และ `--no-cache`

> **Windows:** ถ้า console แสดงภาษาไทยเป็น `?????` ให้ตั้ง
> `$env:PYTHONUTF8="1"` ก่อนรัน

## ข้อจำกัดที่ต้องรู้

### 1. ระบบทะเบียนไม่มีข้อมูล prerequisite และแผนเทอม

ค้นทุกหน้าที่เกี่ยวข้องแล้วได้ **0 ผลลัพธ์** ทุกคำ: `บังคับก่อน`, `ผ่านรายวิชา`,
`ปีที่`, `ภาคการศึกษา`, `แผนการเรียน`

→ เรื่อง "ต้องเรียนคณิต 1 ก่อนคณิต 2" หรือ "วิชานี้ฟิกซ์ปี 2 เทอม 1"
**ไม่มีในระบบ การ login ก็ไม่ช่วย** ต้องกรอกมือจาก มคอ.2 ลงตาราง
`prerequisites` และ `curriculum_rules` (ทั้ง 2 ตารางบังคับใส่ `source`
เพื่อให้บอทอ้างอิงได้และตรวจย้อนหลังได้)

หลักสูตร MDI มีวิชาบังคับ 18 วิชา + ฝึกงาน 1 → กรอกครั้งเดียวประมาณ 1-2 ชม.

### 2. ต้อง parse ด้วย `lxml` ห้ามใช้ `html.parser`

HTML ของ Vision Net มี `</div>` ที่ไม่มีคู่ ทำให้ `html.parser` **ตัด `<td>` ทิ้ง**

```
html.parser : 2/4 แถวคอลัมน์ครบ  ← ข้อมูลคลาดคอลัมน์
lxml        : 4/4 แถวคอลัมน์ครบ
```

นี่เป็นสาเหตุที่ scraper รุ่นก่อนได้ค่า `grade = "3"` ทุกวิชา และ
`semester = "4.5"` (จริง ๆ เป็นคอลัมน์อื่น)

### 3. encoding เป็น `windows-874` ไม่ใช่ UTF-8

ต้อง `r.encoding = "cp874"` ทุกครั้ง ไม่งั้นภาษาไทยเพี้ยน

### 4. `coursecode` ต้องเป็น 7 หลักเต็ม

ค้น `7071` ได้ 0 ผลลัพธ์ ไม่ใช่ partial match → ต้องยิงทีละวิชา
(68 วิชา × 4 เทอม = 272 request ใช้เวลา ~4 นาทีที่ delay 0.7)

### 5. เว็บไม่เสถียร

`Student_Studyplan.asp`, `class_info_5.asp` (ไม่ใส่ param) คืน **HTTP 500**
และ `e-activity.rmu.ac.th` ล่มทั้งเว็บ → มี cache ลงดิสก์ + retry แบบ
exponential backoff และ **ห้าม fetch สดตอน user ถาม**

ผลตรวจ `e-activity.rmu.ac.th` ทุก path:

```
/            500      /login      404
/index.php   500      /home       404
                      /activity   404
```

→ ไม่ใช่แค่หน้าแรกล่ม แต่เข้าไม่ได้เลย **ข้อมูลกิจกรรมจึงยัง scrape ไม่ได้**

### 6. ลิงก์เสียในเว็บต้นทาง

ตรวจ 35 ลิงก์แล้วพบ:

| ปัญหา | ตัวอย่าง |
|---|---|
| URL ซ้อน scheme | `http://https://sci.rmu.ac.th/...` (พบในหน้า sci.rmu จริง) |
| ไฟล์หาย 404 | `cc.rmu.ac.th/file/e-mail_std_.pdf` |
| `.doc` 404 แต่ `.docx` 200 | แบบฟอร์มแจ้งเปลี่ยนเวลาฝึกงาน |
| WAF บล็อก bot 403 | `ocsc.go.th/scholarship` |

→ `scrape_documents.py` จึง **ตรวจทุกลิงก์ด้วย GET stream** ก่อนบันทึก
(ไม่ใช้ HEAD เพราะเซิร์ฟเวอร์ RMU หลายตัวตอบ 405/500 กับ HEAD แต่ 200 กับ GET)

### 7. `login.asp` ใช้ไม่ได้ตามที่คิด

**ตัดเรื่อง login ออกจาก scope แล้ว** — บันทึกไว้เผื่ออนาคต (ทดสอบแล้ว):
POST ไปที่ **`validate.asp`** ไม่ใช่ `login.asp`, ใช้ field
**`f_uid`/`f_pwd`** ไม่ใช่ `txtUsername`/`txtPassword`, และต้องแนบ
**`BUILDKEY`** ที่สุ่มใหม่ทุก request (ทดสอบได้ `33178`, `41604`, `66563`)
→ ต้อง GET `login.asp` มา parse ก่อนเสมอ

### 8. ไม่มี มคอ.2 เผยแพร่ออนไลน์

ค้นแล้วทุกที่ — `promo-curriculum.rmu.ac.th` (หน้ารายการหลักสูตรคณะ IT
คืน HTML ว่าง), `rmu.ac.th/download`, `sci.rmu.ac.th/?page_id=443`
**ไม่มีไฟล์ มคอ.2 ของหลักสูตรใดเลย** พบแต่ มคอ.3 (รายวิชา ไม่ใช่หลักสูตร)

→ `prerequisites` / `curriculum_rules` ต้องขอไฟล์จากคณะหรือกรอกจากเล่มจริง

## โครงสร้างไฟล์

```
kb/
  schema.py             SQLite schema (14 ตาราง) + connect()
  client.py             HTTP client: cp874, lxml, retry, rate limit, cache
  scrape_programs.py    ลิสต์หลักสูตร + โครงสร้าง (category tree)
  scrape_courses.py     คำอธิบายรายวิชา
  scrape_offerings.py   ตารางสอน + สรุป offering_pattern
  scrape_documents.py   ลิงก์เอกสาร/แบบฟอร์ม + ตรวจลิงก์ตาย
  scrape_instructors.py ข้อมูลอาจารย์ + cross-check กับตารางสอน
  verify.py             ตรวจความถูกต้อง (อ่านอย่างเดียว)
  data/
    rmu_kb.db           database (gitignored)
    raw/                HTML cache (gitignored)
```

### ตารางสำคัญ

| ตาราง | ใช้ทำอะไร |
|---|---|
| `programs` | หลักสูตร + หน่วยกิตรวม |
| `categories` | หมวด/กลุ่มวิชาแบบต้นไม้ + `selection_mode` (required/elective) |
| `courses` | รายวิชา + `description_th` สำหรับ embedding |
| `program_courses` | วิชาอยู่หมวดไหนของหลักสูตรไหน |
| `offerings` | หมู่เรียนที่เปิดจริง + ที่นั่งเหลือ |
| `offering_slots` | คาบเรียนแยก field (`day_code`, `start_min`, `end_min`) → ตรวจตารางชน |
| `offering_patterns` | วิชานี้มักเปิดเทอมไหน |
| `documents` | ลิงก์เอกสาร/แบบฟอร์ม + `keywords` ไทย + `is_available` |
| `instructors` | อาจารย์ + `name_normalized` สำหรับ match ชื่อ |
| `instructor_affiliations` | อาจารย์สังกัดสาขาไหน (many-to-many) |
| `prerequisites` | **กรอกมือ** — วิชาบังคับก่อน |
| `curriculum_rules` | **กรอกมือ** — แผนปี/เทอมตามหลักสูตร |

## ขั้นถัดไป

1. กรอก `prerequisites` + `curriculum_rules` จาก มคอ.2
2. เขียน planner (topological sort + greedy fill) — **ต้องเป็น deterministic code
   ห้ามให้ LLM คำนวณ** เพราะ prereq/หน่วยกิตเป็น graph + arithmetic ที่ LLM คิดผิดได้
3. ต่อ LINE webhook + LIFF (ต้อง verify ID token ที่ `POST /oauth2/v2.1/verify`
   ห้ามเชื่อ `userId` ที่ client ส่งมา — LINE เตือนไว้ในเอกสารเอง)
4. LLM ทำหน้าที่ *เรียบเรียงคำอธิบาย* จากผล planner เท่านั้น (retrieve → generate = RAG)
