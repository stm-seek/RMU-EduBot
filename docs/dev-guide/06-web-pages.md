# 06 — หน้าเว็บ 2 หน้า (LIFF และ /admin)

ทั้งสองหน้าเป็น **HTML ไฟล์เดียว ไม่มี build step** ไม่มี React/Vue/npm
เพราะเปิดจากเซิร์ฟเวอร์ FastAPI ตัวเดียวกัน แก้แล้วรีเฟรชเห็นผลทันที
(เหตุผลเชิงเทคนิค: โปรเจกต์นี้ตั้งใจให้ deploy ด้วยการรัน Python ตัวเดียว
ไม่ต้องมี Node.js บนเครื่องเซิร์ฟเวอร์)

## 6.1 หน้า LIFF — สำหรับนักศึกษา (`/liff`)

`web/liff/index.html` · ชื่อหน้า "วิชาที่ผ่านแล้ว"

**ทำอะไร:** ให้นักศึกษาติ๊กว่าผ่านวิชาอะไรแล้ว เพราะข้อมูลนี้เป็นข้อมูลเดียว
ที่ต้องล็อกอินระบบทะเบียนจึงจะรู้ — เราจึงถามเจ้าตัวตรง ๆ แทนการขอรหัสผ่าน

**เส้นทางการทำงาน**

```
กดปุ่ม "ติ๊กวิชาที่ผ่านแล้ว" ในแชท
   → เปิด LIFF ในแอป LINE
   → LIFF ให้ ID token มา
   → POST /api/liff/login  → เซิร์ฟเวอร์ส่ง token ไปให้ LINE ตรวจที่
                              POST /oauth2/v2.1/verify แล้วใช้ค่า sub
                              → hash เป็น user_hash
   → POST /api/liff/state             ดึงแผนการเรียน + วิชาที่ติ๊กไว้ + % ความก้าวหน้า
   → POST /api/liff/completed_courses บันทึกชุดวิชาที่ผ่าน แล้วคืนสถานะใหม่ทั้งก้อน
```

**จุดสำคัญด้านความปลอดภัย:** เซิร์ฟเวอร์ **ห้ามเชื่อ `userId` ที่ client ส่งมา**
ต้อง verify ID token ฝั่งเซิร์ฟเวอร์เสมอ (LINE เตือนเรื่องนี้ในเอกสารเอง)
ถ้าไม่ทำ ใครก็ยิง API ดูข้อมูลของคนอื่นได้ด้วยการเปลี่ยนตัวเลข

**กับดักตอนตั้งค่า:** LIFF อยู่ใต้ **LINE Login channel ซึ่งเป็น channel คนละใบ
กับ Messaging API** ไม่มี access token ให้ใส่ (ใช้แค่ `LIFF_ID` +
`LINE_LOGIN_CHANNEL_ID`) และเลขหน้าขีดของ `LIFF_ID` ต้องตรงกับ channel id นั้น

หน้านี้ **ขึ้นคำเตือนไว้** ว่าลำดับวิชาที่แนะนำยังไม่ใช่เงื่อนไขวิชาบังคับก่อน
เพราะตาราง `prerequisites` ว่าง — เจตนาให้ผู้ใช้รู้ขอบเขตของคำตอบ

## 6.2 หน้า /admin — สำหรับเจ้าหน้าที่/อาจารย์

`web/admin/index.html` + `app/admin.py` + `app/admin_repo.py` · **เทส 140 ตัว**

**ทำอะไร:** แก้ข้อมูลที่บอทเอาไปตอบนักศึกษา โดยไม่ต้องแตะโค้ดและไม่ต้องรีสตาร์ต

| แท็บ | แก้อะไร |
|---|---|
| ภาพรวม | จำนวนแถวแต่ละตาราง + งานที่ค้าง (ตารางไหนยังว่าง) |
| ถาม-ตอบ (`faqs`) | คำถาม-คำตอบของชั้นที่ 2 + คำถามรูปแบบอื่น (variants) |
| เอกสาร (`documents`) | ชื่อ/หมวด/ลิงก์เอกสารและคำร้อง |
| อาจารย์ (`instructors`) | ชื่อ ตำแหน่ง อีเมล สังกัด |
| แผนการเรียน (`curriculum_rules`) | วิชาในแต่ละเทอมของหลักสูตร |
| วิชาบังคับก่อน (`prerequisites`) | เงื่อนไข hard / soft / concurrent + **ช่อง "ที่มาของข้อมูล" บังคับกรอก** |
| คำถามที่ตอบไม่ได้ | รายการจาก `chat_logs` ที่ระบบตอบไม่ได้ → ใช้ตัดสินใจว่าจะเขียน FAQ อะไรต่อ |
| ประวัติการแก้ | ใครแก้อะไรเมื่อไร (`admin_audit_logs`) |

### การตัดสินใจออกแบบที่สำคัญ (เขียนลงเล่มได้)

**(1) ไม่มีปุ่มลบทั้งหน้า — มีแต่ปุ่ม "ปิดการใช้งาน"**
เพราะ scraper จะดึงแถวที่ถูกลบกลับมาเงียบ ๆ ในรอบถัดไป ปุ่มปิดตั้งค่า
`is_active = false` แทน และ **ต้องแก้ฝั่งอ่านให้กรอง `is_active` ด้วย**
(แก้แล้ว 11 จุดใน `app/repository.py`) ไม่งั้นปุ่มปิดไม่มีผลอะไรเลย

**(2) ล็อกอินด้วย username + password ของระบบเราเอง (ไม่ใช่ LINE Login)**
เดิมใช้ LINE Login + รายชื่อ hash ใน `.env` ซึ่งเพิ่ม/ถอนคนต้องแก้ไฟล์บนเครื่อง
จริงแล้วรีสตาร์ตเซิร์ฟเวอร์ และคนที่จะเป็นผู้ดูแลต้องไปขุด hash ของตัวเองจาก
log ก่อน — ขั้นตอนที่ส่งต่อให้เจ้าหน้าที่ทำเองไม่ได้จริง
ตอนนี้บัญชีอยู่ในตาราง `admin_accounts` เพิ่ม/ถอน/รีเซ็ตรหัสได้โดยไม่ต้องรีสตาร์ต

```powershell
$env:PYTHONUTF8='1'
python scripts/admin_user.py --username somchai      # สร้างใหม่ / รีเซ็ตรหัส
python scripts/admin_user.py --list                  # ดูว่ามีใครอยู่
python scripts/admin_user.py --deactivate somchai    # ถอนสิทธิ์ (ไม่ลบแถว)
```

**ไม่มีหน้าเว็บให้สมัครสมาชิกโดยเจตนา** — ประตูเดียวที่สร้างบัญชีได้คือสคริปต์นี้
ซึ่งต้องรันบนเครื่องที่มีไฟล์ `.env` จริง และ**รับรหัสผ่านทาง prompt เท่านั้น**
ไม่มีอาร์กิวเมนต์ให้พิมพ์รหัสในบรรทัดคำสั่ง (ค่าที่พิมพ์จะไปนอนใน history
ของ shell และใน process list ของเครื่อง)

**(3) เก็บรหัสผ่านด้วย scrypt จาก `hashlib` ของ Python เอง**
เก็บเป็นสตริงเดียว `scrypt$<n>$<r>$<p>$<salt>$<hash>` — **ฝังพารามิเตอร์ความหนัก
ไว้ในสตริง** เพื่อว่าวันหนึ่งขึ้นค่าความหนักได้ทันทีสำหรับรหัสที่ตั้งใหม่
โดยที่รหัสเก่ายังล็อกอินผ่านด้วยค่าเดิมของตัวเอง (ถ้าเก็บแค่ hash เปล่า ๆ
การขึ้นค่าความหนักเท่ากับบังคับล้างรหัสผ่านของทุกคน) · salt สุ่มต่อแถว
· เทียบค่าลับด้วย `hmac.compare_digest` (constant-time) เท่านั้น
· **ห้าม log รหัสผ่าน / hash / cookie token** ไม่ว่ากรณีใด

**(4) fail closed — ตั้งไม่เสร็จ = ไม่มีใครเข้าได้ ไม่ใช่เข้าได้ทุกคน**
ไม่มีบัญชีที่ยัง active = 403 · `ADMIN_SESSION_SECRET` ว่าง = 503
และข้อความที่ส่งออกไป **ไม่บอก**ว่าระบบยังตั้งไม่เสร็จ (log ฝั่งเราบอกตรง ๆ)

**(5) ข้อความปฏิเสธตอนล็อกอินเหมือนกันเป๊ะ** ทั้งกรณีไม่มีบัญชีชื่อนั้นและกรณี
รหัสผิด และกรณีไม่มีบัญชีก็ยัง **hash หลอกหนึ่งครั้ง** ให้เวลาตอบใกล้เคียงกัน
ไม่งั้นหน้านี้กลายเป็นเครื่องมือไล่ตรวจว่าใครเป็นผู้ดูแล

**(6) หน้า HTML เปิดดูได้โดยไม่ต้องล็อกอินโดยเจตนา** (ตัวหน้าไม่มีข้อมูลอยู่ในตัว)
ตัวกันคนอยู่ที่ `require_admin` ของทุก endpoint `/api/admin/*`

**(7) allowlist ของตารางที่แก้ได้** `TABLE_KEYS` ใน `app/admin_repo.py` เป็น
ตัวจริงที่กำหนดว่าปุ่มปิดแตะตารางไหนได้และต้องใช้กุญแจอะไร — ส่งกุญแจไม่ครบ
= `UPDATE` ขาด `WHERE` = ปิดทั้งตารางในคลิกเดียว จึงกันไว้สองชั้น
(ตอบ 400 ก่อนแตะ DB + มีเทสนับจำนวน placeholder ใน SQL)

## 6.3 endpoint ทั้งหมดของระบบ

| Method + path | ใครเรียก | ทำอะไร |
|---|---|---|
| `POST /webhook` | LINE | รับ event → ตรวจลายเซ็น → ตอบ 200 → ทำงานเบื้องหลัง |
| `GET /health` | เรา/monitoring | บอกว่าตั้งค่าอะไรแล้วและต่อ DB ได้จริงไหม |
| `GET /` | เบราว์เซอร์ | หน้าแรกสั้น ๆ บอกว่าเซิร์ฟเวอร์นี้คืออะไร |
| `GET /liff` | นักศึกษา | หน้าติ๊กวิชาที่ผ่าน |
| `POST /api/liff/login` | หน้า LIFF | ตรวจ ID token กับ LINE → คืน `user_hash` |
| `GET /api/liff/config` | หน้า LIFF | LIFF ID + รหัสหลักสูตร + เพดานหน่วยกิต |
| `POST /api/liff/state` | หน้า LIFF | แผนการเรียน + วิชาที่ติ๊ก + ตัวเลขความก้าวหน้า |
| `POST /api/liff/completed_courses` | หน้า LIFF | บันทึกวิชาที่ผ่าน |
| `GET /admin` | เจ้าหน้าที่ | หน้าจัดการข้อมูล |
| `POST /api/admin/login` `/logout` | หน้า admin | ล็อกอิน/ออก (cookie session) |
| `POST /api/admin/state` `/config` | หน้า admin | ดึงข้อมูลทุกตารางที่แก้ได้ |
| `POST /api/admin/faq` `/document` `/instructor` `/curriculum_rule` `/prerequisite` | หน้า admin | เพิ่ม/แก้แถว |
| `POST /api/admin/toggle` | หน้า admin | เปิด/ปิดการใช้งานแถว (แทนการลบ) |
| `POST /api/admin/chat_logs` | หน้า admin | ดูคำถามที่ระบบตอบไม่ได้ |
