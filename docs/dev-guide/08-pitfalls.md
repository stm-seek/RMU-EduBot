# 08 — กับดักและวิธีแก้ (ทุกข้อเจอมาจริงแล้ว)

ใช้เป็นวัตถุดิบหัวข้อ "ปัญหาและอุปสรรค" / "ข้อจำกัดของระบบ" ในบทที่ 5 ได้ตรง ๆ

## 8.1 สภาพแวดล้อม Windows

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Psycopg cannot use the 'ProactorEventLoop' to run in async mode` | uvicorn บังคับ event loop ที่ psycopg แบบ async ใช้ไม่ได้ | รันด้วย `python run.py` เท่านั้น (ตั้ง `SelectorEventLoop` ให้ก่อน) การตั้ง event loop *policy* ไม่ช่วย เพราะ uvicorn ส่ง loop factory ให้ `asyncio.Runner` ตรง ๆ |
| log ภาษาไทยออกมาเป็น `?????` | console เป็น cp874/cp1252 | ตั้ง `$env:PYTHONUTF8='1'` **ก่อน** สั่งรัน (process ลูกรับค่าไปตอนสร้าง) |
| `--reload` แล้วต่อฐานข้อมูลไม่ได้ | process ลูกที่ reload สร้าง loop ใหม่เอง | ใช้ `--reload` เฉพาะตอนแก้ส่วนที่ไม่ใช้ DB |
| ฆ่า process เบื้องหลังไม่ได้ | `$!` ของ bash ให้ MSYS PID ที่ `taskkill` ใช้ไม่ได้ | ใช้ `Start-Process -PassThru` แล้วเก็บ `$p.Id` |
| error `10048` ตอนสตาร์ต | พอร์ตชนกับโปรเจกต์อื่นในเครื่อง | `Get-NetTCPConnection -LocalPort 8001 -State Listen` ดูว่าใครยึด (พอร์ต 8000 ถูกโปรเจกต์อื่นยึดอยู่ บอทนี้จึงใช้ 8001) |
| Docker Desktop เปิดไม่ได้ | ต้องมี WSL2 + Virtual Machine Platform + virtualization ใน BIOS | `wsl.exe --install --no-distribution` (Administrator) แล้ว reboot — หรือเลี่ยงไปติดตั้ง Postgres ตรง ๆ / ใช้ Supabase, Neon ที่มี pgvector มาให้แล้ว |

## 8.2 การเชื่อมต่อกับ LINE

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| Verify ไม่ผ่าน: `COULD_NOT_CONNECT` | tunnel ไม่ทำงาน / URL เปลี่ยนแล้ว | เปิด tunnel ใหม่ แล้วตั้ง webhook ใหม่ **ทุกครั้ง** (URL ของ cloudflared สุ่มใหม่ทุกรอบ) |
| Verify ไม่ผ่าน: `ERROR_STATUS_CODE` | ถึงเซิร์ฟเวอร์แล้วแต่ตอบไม่ใช่ 200 | ดู log — **ห้ามไปแก้เรื่อง signature** เพราะปุ่ม Verify ของ LINE ส่ง signature มาถูกต้องอยู่แล้ว (ห้ามเปิดช่องยกเว้นการตรวจลายเซ็นให้ request ที่ไม่มี event) |
| ตั้ง tunnel ถูกทุกอย่างแต่ไม่ติด (tailscale funnel) | พังที่ระดับ ingress ของบริการเอง — TLS อ่านกลับได้ 0 ไบต์ | อย่าเสียเวลาแก้ ใช้ cloudflared |
| ผู้ใช้ได้ข้อความซ้ำ | ตอบ 200 ช้าเกิน LINE จึง retry webhook | ต้องตอบ 200 ก่อนแล้วทำงานใน BackgroundTasks (โครงสร้างนี้ทำไว้แล้ว) |
| Rich Menu ไม่ขึ้น | LINE for PC ไม่แสดง Rich Menu | ทดสอบบนมือถือ |
| เปลี่ยนภาพ Rich Menu ไม่ได้ | LINE ไม่ให้แก้ภาพของเมนูที่อัปโหลดแล้ว | สร้างใบใหม่ → ตั้ง default → ลบใบเก่า (`make rich-menu-list` / `rich-menu-delete`) |
| ปุ่มกดไม่ตรงช่อง | พิกัดในโค้ดไม่ตรงกับไฟล์ภาพ | พิกัดใน `app/line/rich_menu.py` **วัดจากภาพจริง** เปลี่ยนภาพต้องวัดใหม่ ไม่ใช่หาร 3 หาร 2 |
| LIFF ใส่ token ไม่ได้ | LIFF อยู่ใต้ **LINE Login channel** คนละใบกับ Messaging API | ใช้ `LIFF_ID` + `LINE_LOGIN_CHANNEL_ID` และเลขหน้าขีดของ `LIFF_ID` ต้องตรงกับ channel id |

## 8.3 AI / LLM

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ผู้ใช้เห็น "ระบบขัดข้อง" เป็นระยะ ๆ ทั้งที่คำถามปกติ | free tier ของ Gemini คืน HTTP 503 "high demand" แบบสุ่ม (วัดได้ 503 ในการยิงครั้งแรก 7/7 ครั้ง) | retry สั้น ๆ + สลับโมเดลสำรอง ใต้เพดานเวลารวม (ทำแล้วใน `app/llm.py`) |
| ชื่อโมเดลใช้ไม่ได้ | โมเดลสาย 2.x ปลดระวางแล้ว | ใช้ชื่อที่ยืนยันกับ API จริงแล้วเท่านั้น และรุ่น `flash-lite` เร็วกว่า `flash` มาก |
| embedding มิติไม่ตรงกับ schema | `gemini-embedding-2` คืน 3,072 มิติโดย default แต่ schema เป็น `vector(768)` | ต้องส่งพารามิเตอร์ `dimensions` ขอ 768 (`EMBEDDING_DIM` ล็อกไว้ที่ 768) |
| error 400/401/403 | คีย์หรือ payload ผิด | **ไม่ retry ไม่สลับโมเดล** เพราะลองใหม่ก็ผิดเหมือนเดิม — ต้องไปแก้ค่าตั้งต้น |

## 8.4 ฐานข้อมูลและข้อมูล

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `psql: FATAL: role "postgres" does not exist` | ผู้ใช้ของฐานนี้คือ `rmubot` | `docker exec -i rmu_bot_db psql -U rmubot -d rmu_bot` |
| INSERT ลง `chat_logs` พังทั้งแถว | เพิ่มค่า `answered_by` ใหม่ในโค้ดแต่ไม่ได้เพิ่มใน CHECK constraint | ต้องเขียน migration เพิ่มค่าด้วย (ล่าสุดคือ `007_answered_by_faq.sql` เพิ่มค่า `faq`) |
| รัน seed ซ้ำแล้วพัง | เคยเป็นบั๊ก (seed ไม่ idempotent) | แก้แล้วด้วย `ON CONFLICT ... DO UPDATE` และมีเทสคุม |
| นำเข้าแผนการเรียนแล้วข้อมูลหายเงียบ ๆ | รหัสวิชาในแผนเป็น 7 หลัก + มีเลขรุ่นต่อท้าย, `courses` มีรหัสซ้ำ, และ `split(";")` ตัดข้อมูลทิ้ง | `scripts/import_curriculum_rules.py` **นับจำนวนก่อน/หลังให้ตรงกัน** ทุกครั้ง |
| ปุ่ม "ปิดการใช้งาน" ในหน้า admin กดแล้วไม่มีผล | ฝั่งอ่านไม่ได้กรอง `is_active` | ต้องกรองในทุก query ที่บอทใช้อ่าน (แก้แล้ว 11 จุด) |
| ตั้งเครื่องใหม่แล้วหน้า admin ใช้ไม่ได้ | `make migrate` รันถึงแค่ `005` | รัน `006`, `007`, `008` เพิ่มเอง หรือใช้ `make db-reset` (Postgres รันทุกไฟล์ตอนสร้าง volume ใหม่) |

## 8.5 กับดักตอนอ่าน log และตอนสรุปผล

* **log แยกสองไฟล์** — access log ของ uvicorn ออก stdout, log ของแอปออก stderr
  อ่านผิดไฟล์แล้วจะสรุปผิดว่า request ไม่เข้ามาเลย
* **เซิร์ฟเวอร์ที่รันอยู่อาจเป็นโค้ดเก่า** — แก้โค้ดแล้วต้องรีสตาร์ตก่อนทดสอบบน
  LINE (เคยเสียเวลาไล่บั๊กที่แก้ไปแล้ว เพราะ process เก่ายังอยู่)
* **`answered_by=search` ไม่ได้แปลว่าตอบถูก** — เคยเจอกรณีค้นเจอเอกสารที่ชื่อ
  คล้ายแต่ผิดเรื่อง (false positive) เวลาสรุปผลในบทที่ 4 ต้องดูเนื้อคำตอบด้วย
  ไม่ใช่นับแค่ป้าย
* **คำถามที่ระบบยังตอบไม่ได้จริง** เช่น "ดรอปวิชา" — ในคลังเอกสารไม่มีคำร้องถอน
  รายวิชา จึงตอบไม่ได้ ไม่ใช่บั๊กแต่เป็นช่องว่างของข้อมูล

## 8.6 เรื่องความปลอดภัยที่ควรรู้ก่อนขึ้นใช้งานจริง

* **`/docs` และ `/openapi.json` เปิดให้ใครก็เข้าได้** — `app/main.py` ไม่ได้ตั้ง
  `docs_url=None` ตอนสร้าง `FastAPI()` ทำให้หน้าเอกสาร API อัตโนมัติเปิดอยู่ทุก
  สภาพแวดล้อม ตัว endpoint ยังกันด้วย `require_admin` อยู่ครบ แต่คนนอกเห็น
  รายการ endpoint ทั้งหมดได้ ถ้าจะขึ้นใช้งานจริงควรปิดหรือใส่รหัสก่อน
  (ข้อดีคือระหว่างพัฒนามันคือภาพประกอบชั้นดี — ดู `a14-swagger-docs.png`)
* **บัญชีผู้ดูแลลบไม่ได้ตามการออกแบบ** — ตาราง `admin_accounts` ไม่มี DELETE
  ปิดได้แค่ `is_active = false` เพราะฉะนั้นอย่าสร้างบัญชีทดลองเล่น ๆ
* **ตารางว่าง = ไม่มีใครเข้าได้** ไม่ใช่ใครก็เข้าได้ สร้างบัญชีแรกได้ทางเดียว
  คือ `python scripts/admin_user.py` ซึ่งถามรหัสผ่านแบบพิมพ์สด ไม่รับผ่าน argument
