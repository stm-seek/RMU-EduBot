## 9.2 ข้อเท็จจริงที่ต้องแก้ให้ตรงก่อนเขียน

**ชื่อหลักสูตร** — ในฐานข้อมูล (ดึงจากระบบทะเบียนโดยตรง) คือ

```
รหัส 643170151  ชื่อ "การจัดการนวัตกรรมดิจิทัล"
คณะเทคโนโลยีสารสนเทศ  วิทยาศาสตรบัณฑิต  ปริญญาตรี 4 ปี ภาคปกติ  120 หน่วยกิต
```

ร่างบทที่ 3 เขียนว่า "สาขาวิชาดิจิทัลมีเดียอินโนเวชัน" — **ไม่ตรงกับระบบทะเบียน**
ต้องเลือกชื่อเดียวแล้วใช้ให้ตรงกันทั้งเล่ม (แนะนำใช้ชื่อตามระบบทะเบียน)

**ปีที่อ้างอิง** — ข้อมูลตารางสอนที่นำเข้าใหม่สุดคือ **ปีการศึกษา 2568 เทอม 2**
ยังไม่ได้ดึงข้อมูลปี 2569 ถ้าเล่มจะเขียนว่า "ข้อมูลปัจจุบัน" ต้องระบุวันที่ดึงข้อมูล

## 9.3 สิ่งที่ห้ามเคลม (README ที่รากโปรเจกต์เคลมเกินไว้ 11 จุด)

| README เขียนว่า | ความจริง |

| "เทส 512 unit + 46 doctests" | ตัวเลขปัจจุบันคือ **769 unit + 63 doctest + 103 integration** |
| admin ล็อกอินด้วย LINE Login + `ADMIN_USER_HASHES` | เปลี่ยนเป็น **username + password** ในตาราง `admin_accounts` แล้ว |
| "ยังใช้ text + Quick Reply ก่อน (ไม่มี Flex)" | มี `app/line/flex.py` แล้ว |
| Quick start บอกพอร์ต 8000 | ใช้จริงคือ **8001** |

**ห้ามเคลมสิ่งเหล่านี้เด็ดขาด** เพราะระบบทำไม่ได้จริง และตรวจสอบง่ายมาก:

1. ❌ "ระบบตรวจสอบวิชาบังคับก่อน (prerequisite) ได้" — ตาราง `prerequisites`
   **ว่างทั้งตาราง** ระบบใช้ลำดับจากแผนการเรียนแทน และ**บอกผู้ใช้ตรง ๆ**
   ว่านี่เป็นลำดับที่แนะนำ ไม่ใช่เงื่อนไขบังคับ
2. ❌ "ระบบทำ RAG / ค้นด้วยความหมายจากระเบียบมหาวิทยาลัย" — `rag_chunks` ว่าง
   โครงสร้าง pgvector พร้อมแล้วแต่ยังไม่มีเนื้อหาที่ index
3. ❌ "ระบบเชื่อมกับระบบทะเบียนของมหาวิทยาลัย" — ไม่เชื่อม เป็นการดึงข้อมูล
   สาธารณะมาเก็บไว้เอง (แบบ offline) และ**ไม่ล็อกอินแทนนักศึกษา**
4. ❌ "ระบบรู้เกรดของนักศึกษา" — ไม่เก็บเกรด ผู้ใช้พิมพ์ GPAX มาให้ตอนคำนวณเท่านั้น
5. ❌ "ตอบคำถามเรื่องกิจกรรม/จิตอาสาได้" — เว็บกิจกรรมคืน HTTP 500 ทุก path
6. ❌ "มีข้อมูลติดต่ออาจารย์ครบ" — มีชื่อ/อีเมล แต่**ไม่มีเบอร์โทรและห้องพัก**
   (เว็บคณะไม่เผยแพร่ 0/28 คน)
7. ❌ "ผ่านการทดสอบกับผู้ใช้จริงจำนวน N คน" — **ยังไม่ได้เก็บข้อมูลส่วนนี้**
   ถ้าจะมีในเล่มต้องไปทดลองใช้จริงกับนักศึกษาก่อน

## 9.5 คำศัพท์ไทย-อังกฤษ (ใช้ให้ตรงกันทั้งเล่ม)

| อังกฤษ | ไทยที่แนะนำ |
|---|---|
| webhook | การเรียกกลับอัตโนมัติ (webhook) |
| reply token | โทเคนสำหรับตอบกลับ |
| Rich Menu / Quick Reply | เมนูรูปภาพ / ปุ่มตอบด่วน |
| LIFF (LINE Front-end Framework) | เว็บแอปภายในแอปไลน์ (LIFF) |
| postback | ข้อมูลย้อนกลับจากการกดปุ่ม (postback) |
| LLM (Large Language Model) | โมเดลภาษาขนาดใหญ่ |
| embedding / vector | เวกเตอร์แทนความหมายของข้อความ |
| RAG (Retrieval-Augmented Generation) | การสร้างคำตอบโดยดึงข้อมูลมาประกอบ |
| fallback | การตอบเมื่อระบบไม่เข้าใจคำถาม |
| deterministic | ให้ผลแน่นอนคงเดิม (ไม่สุ่ม) |
| trigram similarity (`pg_trgm`) | ความคล้ายระดับตัวอักษรสามตัว |
| unit test / integration test | การทดสอบหน่วย / การทดสอบเชื่อมต่อ |
| idempotent | รันซ้ำได้ผลเหมือนเดิม |
| hash + pepper | การแปลงค่าทางเดียว + ค่าลับประจำระบบ |
| scrape | การดึงข้อมูลจากหน้าเว็บ |
| connection pool | แหล่งรวมการเชื่อมต่อฐานข้อมูล |

## 9.6 ประโยคที่ปลอดภัยและตรงความจริง (ยกไปใช้ได้)

> ระบบตอบคำถามด้วยสถาปัตยกรรม 3 ชั้น โดยให้ชั้นที่ตอบจากฐานข้อมูลโดยตรงทำงาน
> ก่อนเสมอ และใช้โมเดลภาษาขนาดใหญ่เฉพาะกรณีที่ไม่มีคำตอบที่แน่นอนอยู่ในฐานข้อมูล
> เพื่อควบคุมความถูกต้องของข้อมูลและต้นทุนการเรียกใช้บริการ

> การคำนวณที่มีผลต่อการตัดสินใจของนักศึกษา เช่น จำนวนหน่วยกิตคงเหลือ ลำดับวิชา
> ที่ควรลงทะเบียน และเกรดเฉลี่ยเป้าหมาย ถูกพัฒนาเป็นโปรแกรมที่ให้ผลแน่นอน
> (deterministic) โดยไม่มอบหมายให้โมเดลภาษาเป็นผู้คำนวณ

> เมื่อระบบไม่พบข้อมูลอ้างอิง ระบบจะแจ้งผู้ใช้ว่ายังไม่มีข้อมูลในเรื่องนั้น
> พร้อมเสนอหัวข้อที่ตอบได้ แทนการคาดเดาคำตอบ

> ระบบไม่ขอรหัสผ่านระบบทะเบียนของนักศึกษา และจัดเก็บตัวระบุผู้ใช้ในรูปค่าที่
> ผ่านการแปลงทางเดียว (SHA-256 ร่วมกับค่าลับประจำระบบ) โดยไม่จัดเก็บชื่อ
> รหัสนักศึกษา และผลการเรียนรายวิชา
